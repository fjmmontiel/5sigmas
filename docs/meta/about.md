## Para quién es

5sigmas está escrito para quien quiere comprender la IA más allá del calendario de lanzamientos: personas técnicas, responsables de producto y lectores con curiosidad suficiente para exigir el mecanismo detrás de una afirmación.

No busca convertir cada novedad en contenido. Busca construir una biblioteca que siga siendo útil cuando cambien los nombres de los modelos.

## Cómo se construye una pieza

### 1. La pregunta antes que la conclusión

El trabajo empieza definiendo qué se intenta explicar y qué observación podría contradecir la hipótesis inicial.

### 2. La fuente primaria antes que el resumen

Los hechos técnicos se apoyan en papers, código, datasets, benchmarks o documentación oficial. Una fuente secundaria puede orientar la búsqueda, pero no sostiene la afirmación final.

### 3. El mecanismo antes que la analogía

Las analogías sirven para entrar en una idea. La arquitectura, los datos y el proceso causal son los que permiten transferirla a un caso nuevo.

### 4. Los límites antes que el titular

Presupuesto de cómputo, latencia, distribución de datos, definición del benchmark, seguridad, operación y mantenimiento forman parte de la conclusión.

## Política editorial

Las piezas se revisan cuando aparece evidencia que cambia la interpretación, no simplemente cuando se publica un modelo nuevo. Cuando una conclusión contiene estimación o inferencia, se señala como tal.

Ningún artículo utiliza una referencia de segunda mano como fuente principal para un hecho técnico.
