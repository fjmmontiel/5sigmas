Cargar una skill por etapas

El catálogo muestra la descripción de una skill sin cargar todas sus instrucciones.

Cuando la tarea la necesita, se carga el procedimiento y después las referencias pertinentes.

La carga progresiva limita contexto. No aísla el proceso ni concede nuevas autorizaciones.

Un paquete no es un sandbox

Un plugin distribuye una skill, un hook y una integración.

Esos componentes pueden ejecutarse en superficies diferentes, con permisos distintos.

Instalar el paquete no demuestra aislamiento. Hay que inspeccionar cada componente y su entorno.

Delegar un contrato preciso

El padre necesita revisar el diff A, no compartir toda la conversación.

El envelope fija objetivo, archivos permitidos, tools, presupuesto y formato de salida.

El especialista devuelve hallazgos y evidencia sobre A. Un resumen sin identidad no cierra la revisión.

Otra ventana no es otro entorno

Dos agentes tienen contextos de modelo separados, pero comparten el mismo filesystem.

Separar también archivos, tools y red exige controles adicionales. No se deduce del nombre subagente.

La evaluación comprueba cada frontera y los accesos prohibidos, además del éxito de tarea.

Bloquear antes del efecto

Un control preventivo decide antes de ejecutar una escritura. Si la deniega, no hay efecto.

Un hook posterior observa una escritura ya realizada. No puede deshacerla sólo por ejecutarse después.

El orden forma parte del contrato. Hay que probar el evento, el fallo y la decisión real.

Éxito y aislamiento se miden aparte

Un especialista puede resolver la tarea y aun así leer un archivo prohibido.

Otra ejecución respeta el aislamiento, pero entrega un resultado incorrecto. Son fallos diferentes.

La entrega necesita evidencia de tarea y de fronteras sobre la misma ejecución, no una única etiqueta PASS.
