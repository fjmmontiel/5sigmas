Pedir no es ejecutar

El modelo propone ejecutar un test. Todavía no ha ocurrido ningún efecto.

El harness aplica la política y lanza el proceso en un workspace concreto.

Sólo entonces existe un resultado real: salida, errores y código de retorno.

El error cambia el turno

El test rechaza la opción --json que acabamos de añadir.

Ese error vuelve al modelo como observación del código actual.

El agente corrige el parser y repite el test. Una intención no sustituye esta prueba.

Un archivo no es el sistema

Cambiar report() afecta también a quienes consumen su resultado.

Leer sólo la función deja fuera el exportador que espera texto.

La búsqueda amplía el contexto antes de editar. Otro modelo no recupera un dato que no vio.

Mismo modelo, otro control

Dos ejecuciones usan el mismo modelo y proponen el mismo cambio.

Una comprueba el estilo. La otra prueba además el comportamiento anterior.

El segundo control detecta una regresión. El resultado pertenece al sistema completo.

Un PASS necesita identidad

El test de la tarea T7 se ejecutó en W2 sobre la revisión A.

Una edición crea la revisión B. El recibo anterior sigue describiendo A.

Conservar tarea, entorno y revisión evita atribuir ese PASS al código equivocado.

Parar no significa terminar

Con el contrato verificado, el harness puede entregar el resultado.

Si falta una decisión, devuelve el control al usuario.

Si agota el presupuesto, termina incompleto. Son desenlaces distintos, no etapas de éxito.
