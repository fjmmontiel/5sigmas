Separar tres fronteras

La branch señala commits. El workspace contiene los archivos de trabajo.

El sandbox limita efectos sobre archivos, procesos o red.

Separar una copia no demuestra que esté confinada. Hay que comprobar ambas fronteras.

La branch no guarda todo

La referencia de Git apunta al commit A.

Una edición sin commit cambia el archivo, pero no mueve esa referencia.

Procesos y archivos ignorados quedan fuera de ese historial. Un commit no describe todo el entorno.

Dos índices, dos copias

Dos agentes escriben sobre copias distintas del mismo repositorio.

Cada worktree mantiene su propio HEAD e índice: una edición no pisa el archivo del otro.

Eso evita interferencia local de archivos. No concede aislamiento de red ni de servicios.

La base de datos sigue compartida

Los worktrees A y B tienen archivos separados, pero usan la misma base de pruebas.

A borra una fixture. El test de B encuentra cero filas y falla.

En otra ejecución, separar los namespaces evita esta interferencia concreta, no todos los conflictos.

Sin conflicto, con un error

Una tarea cambia el importe de céntimos a euros. Otra añade un consumidor.

Los cambios tocan líneas distintas: Git puede combinarlos sin conflicto textual.

El consumidor espera céntimos y recibe euros. El contrato combinado todavía necesita una prueba.

El cambio ajeno se conserva

El workspace ya tenía una edición humana antes de empezar.

Después aparecen cambios del agente y de otro proceso.

Un cleanup debe distinguir sus propietarios. Revertir todo destruiría trabajo que no era suyo.
