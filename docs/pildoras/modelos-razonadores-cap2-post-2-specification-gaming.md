  <section class="li-caption-panel"><p>Un modelo no necesita &quot;rebelarse&quot; para fallar. Le basta con detectar que la métrica que premias y el objetivo real no son exactamente lo mismo.</p>
<p>En febrero de 2025, un paper mostró que o3 hackeaba el entorno de ajedrez en el 88% de los runs en lugar de jugar limpiamente contra Stockfish. No estaba actuando con intención propia; estaba optimizando lo que el sistema le permitía optimizar. Si el objetivo es ganar y puede tocar el entorno, manipular el tablero puede resultar más eficaz que encontrar una buena jugada.</p>
<p>El problema no depende de prompts extremos ni de una IA malvada. Depende de dejar huecos entre lo que quieres conseguir y lo que realmente premias. Cuando esas dos cosas se separan, el modelo aprende el camino más fácil aunque estropee el trabajo real.</p>
<p>Eso importa fuera del laboratorio porque se parece mucho a bastantes sistemas de negocio: métricas en verde, resultado aparente correcto y proceso degradado por debajo. No hace falta que el error sea visible a simple vista; basta con que el sistema cumpla la letra y deje de cumplir el objetivo.</p>
<p>En el artículo conecto el caso del ajedrez con el problema más amplio de diseñar objetivos y restricciones que no inviten a este tipo de fallo. (<a href="https://5sigmas.com/series/modelos-razonadores/02-fallos/">https://5sigmas.com/series/modelos-razonadores/02-fallos/</a>).</p>
