Best-of-N: generar múltiples respuestas y elegir la mejor
La palanca más simple de test-time compute: más intentos independientes, mejor resultado esperado. Tres variantes con distintos criterios de selección.
Mismo prompt, N ejecuciones independientes con temperatura > 0. El criterio de selección determina qué variante es.

CRITERIO DE SELECCIÓN (PRM)
→ Candidato 1 seleccionado por mayor puntuación media de pasos intermedios
El criterio de selección define la variante. Cada una tiene ventajas distintas según el dominio.
Best-of-N con verificador
N = 4–64
Un ORM o PRM puntúa cada candidato. Se selecciona el de mayor puntuación.
Ideal para: matemáticas y código donde hay un verificador objetivo.
Límite: requiere un modelo de recompensa entrenado o un verificador externo (tests).
Self-consistency (mayoría)
N = 8–40
Se genera N respuestas y se selecciona la que aparece con mayor frecuencia (voto mayoritario sobre el resultado, no la cadena de razonamiento).
Ideal para: preguntas con respuesta discreta (múltiple choice, cálculos con resultado único).
Límite: no funciona si las respuestas son texto libre sin forma canónica comparable.
Beam search (tree-of-thought)
N branches
En lugar de generar candidatos completos, se expanden múltiples ramas en cada paso de la cadena y se podan las de menor puntuación. Exploración estructurada del espacio de razonamiento.
Ideal para: problemas donde el espacio de soluciones tiene estructura jerárquica (ajedrez, planeación, código modular).
Límite: coste computacional muy superior; requiere PRM que pueda puntuar pasos parciales.
Modelo-como-juez
N = 3–8
Un modelo separado (o el mismo, en un rol diferente) evalúa los candidatos y selecciona el mejor según criterios declarados en el prompt del juez.
Ideal para: texto abierto, argumentación, análisis — donde no hay verificador objetivo.
Límite: el juez puede tener los mismos sesgos que el modelo generador. No es un verificador independiente real.
El rendimiento mejora con N de forma sublogarítmica. Los primeros candidatos aportan mucho; los siguientes, cada vez menos.

Pasar de N=1 a N=4 da el mayor salto. De N=32 a N=64 aporta mucho menos a un coste doble.
PRM vs self-consistency
Con PRM el techo es más alto porque el verificador puede detectar la mejor respuesta incluso si no es la más frecuente.
Punto óptimo práctico
Para la mayoría de aplicaciones, N entre 8 y 32 da el mejor ratio rendimiento/coste. Más allá, el coste crece linealmente pero el beneficio se estanca.
