Overthinking: cuando más razonamiento degrada la respuesta
Existe un punto óptimo de tokens de razonamiento. Pasarlo perjudica la calidad, especialmente en tareas simples donde el modelo explora alternativas incorrectas.
Apple Research (2025) documentó el patrón: los modelos encuentran la solución correcta pronto, luego continúan explorando alternativas que la contradicen, y la respuesta final se degrada.
Calidad de la respuesta
+35pp
mejora media al añadir los primeros 500 tokens de razonamiento (vs. respuesta directa)
~1.5K
tokens de razonamiento donde se alcanza el pico en tareas simples (benchmarks Apple 2025)
−18pp
degradación media en tareas simples al pasar de 1.5K a 8K tokens de razonamiento
El overthinking no es que el modelo "piense demasiado" en abstracto — es que el sistema de exploración del razonamiento sigue activo cuando ya debería haber parado.
Token 0–200
Análisis inicial
"El problema pide calcular el área de un triángulo con base 8 y altura 5. La fórmula es A = (b × h) / 2."
La respuesta correcta está disponible
↓
Token 200–500
Primera solución
"A = (8 × 5) / 2 = 40 / 2 = 20. El área es 20 unidades cuadradas."
Correcto. En un sistema sin overthinking, la cadena terminaría aquí.
↓
Token 500–1500
Re-exploración innecesaria
"Espera, debería verificar si hay casos especiales... ¿y si la altura es exterior? ¿Y si las unidades son distintas? Voy a reconsiderar usando la fórmula de Herón por si acaso..."
El modelo duda de una respuesta correcta. Introduce incertidumbre donde no existía.
↓
Token 1500+
Respuesta degradada
"Hay múltiples formas de interpretar este problema. El área podría ser 20 si la altura es perpendicular, pero si consideramos la fórmula de Herón con los lados... necesitaría más información."
La respuesta final es peor que la que el modelo tenía en el token 500.
El overthinking es predecible — aparece más en tareas simples y con presupuestos de tokens excesivos. Las mitigaciones aprovechan ese patrón.
Budget forcing adaptativo
Clasificar la query por complejidad estimada y asignar un budget de tokens proporcional. Preguntas simples → budget bajo. La mayoría de queries cotidianas son simples.
Requiere un clasificador de complejidad o heurísticas domain-specific.
Early stopping por confianza
Si la cadena de razonamiento produce una respuesta con alta probabilidad antes del budget máximo, se cierra la cadena y se usa esa respuesta. No explorar más si ya se tiene una respuesta de alta confianza.
Difícil de calibrar: la confianza del modelo no es perfectamente fiable como señal de corrección.
Instrucción explícita en prompt
Indicar al modelo que, si llega a una conclusión clara, no continúe re-explorando alternativas a menos que haya una razón concreta para dudar. Reduce la re-exploración innecesaria.
Funciona en muchos casos pero no es robusto — el modelo puede ignorar la instrucción en razonamientos largos.
