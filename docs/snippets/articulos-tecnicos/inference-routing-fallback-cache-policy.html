Cuatro decisiones distintas

Cache, model routing, fallback y worker placement no son la misma capa

Primero se aplican restricciones duras. Un cache hit puede evitar inferencia; un miss activa la política de modelo. Sólo después se elige un worker. El fallback ocurre tras un fallo y necesita su propio presupuesto y contrato de compatibilidad.

Lectura: el sistema filtra primero lo que no puede ejecutar correctamente. El cache puede cerrar la request sin inferencia. En un miss, el router elige modelo y después otra capa elige worker. Un fallo no habilita automáticamente fallback: debe quedar presupuesto, ser compatible y no romper semántica por output parcial o efectos externos. La política mejora con evidencia de decisiones y alternativas, no sólo con los casos que eligió.
