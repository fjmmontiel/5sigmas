LLMOps: el ciclo completo para GenAI en producción
Un modelo fundacional no es un producto. Para que funcione de forma fiable hace falta un ciclo de ingeniería completo. Si falta un paso, normalmente tienes una demo, no un sistema.
1
Seleccionar modelo base

Elegir qué modelo fundacional usar: tamaño, proveedor, licencia, coste por consulta.

2
Curar datos de adaptación

Si hay ajuste fino, preparar ejemplos de alta calidad. La calidad pesa más que la cantidad.

3
Adaptar opcional

Ajuste fino supervisado, alineación con feedback humano, o diseño del prompt base con ejemplos representativos.

4
Construir el contexto

Si aplica RAG: cómo se trocean los documentos, cómo se representan y cómo se recupera la información relevante por consulta.

5
Evaluar

Métricas automáticas, revisión humana sobre muestra representativa, y usar otro modelo para evaluar respuestas según criterios definidos.

El paso más subestimado. Sin una forma de medir, no puedes iterar con criterio.
6
Desplegar

API con control de versiones de prompts, monitorización de coste y latencia desde el primer día.

7
Monitorizar y mejorar

Cambios en los temas que llegan, calidad de respuestas, feedback de usuarios. Ajuste de prompts o reentrenamiento según la señal.

Diferencias clave respecto a MLOps clásico
Sin etiquetas limpias

"Fue buena esa respuesta?" es difícil de medir automáticamente con precisión.

Comportamiento probabilístico

El mismo prompt puede dar respuestas distintas en ejecuciones distintas.

El prompt es parte del sistema

Cambiar las instrucciones cambia el comportamiento tanto como cambiar el modelo.

Deriva semántica

Los datos no cambian de forma, cambia el tipo de preguntas que llegan y los temas que emergen.
