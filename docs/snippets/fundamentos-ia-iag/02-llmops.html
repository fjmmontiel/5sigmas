Diseñar el system prompt

Es el código de tu sistema. Define el comportamiento, el tono, los límites y el formato de salida. Una instrucción mal formulada degrada el rendimiento igual que un bug. Se versiona, se testea y se despliega como cualquier artefacto de software.

Evaluar paso crítico

El paso más subestimado y el más decisivo. Como no puedes reentrenar el modelo para corregir un error, la única palanca de mejora es el prompt y el contexto. Sin una forma de medir no puedes iterar con criterio.

Tres enfoques complementarios: métricas automáticas, revisión humana sobre una muestra, y un modelo evaluador que puntúa respuestas según criterios definidos (LLM-as-judge).

Monitorizar y mejorar el prompt

En producción el mundo cambia: los temas derivan, emergen casos que no estaban en los tests, el modelo del proveedor se actualiza. La mejora aquí es iterar sobre el prompt y el contexto. Un cambio de prompt puede romper el sistema silenciosamente si no hay evaluación automatizada.
