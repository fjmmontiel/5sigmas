El entregable útil de un red-team es el test que queda

Un hallazgo que no se convierte en fixture reproducible vuelve a depender de memoria humana en la siguiente release.

01
Hallazgo
Una trayectoria concreta consigue atravesar el sistema.
02
Fixture
Entrada, estado inicial, scopes y budget quedan fijados.
03
Mitigación
Se cambia la frontera que debe detener la cadena.
04
Regresión
El mismo caso corre contra modelo, prompt, retrieval o policy nuevos.
05
Release gate
Si reaparece el efecto, la release no pasa.
Inicio: un incidente reproducible puede convertirse en una propiedad que la CI comprueba de forma continua.
