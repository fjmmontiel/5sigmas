A request is not an action

The model proposes running a test. No effect has occurred yet.

The harness applies policy and starts the process in a specific workspace.

Only then is there a real result: output, errors and an exit code.

An error changes the next turn

The test rejects the --json option we just added.

That error returns to the model as an observation of the current code.

The agent fixes the parser and reruns the test. Intention cannot replace this check.

One file is not the system

Changing report() also affects the code that consumes its result.

Reading only the function misses the exporter that expects text.

Same model, different checks

Two runs use the same model and propose the same change.

One checks style. The other also tests the previous behaviour.

The second check catches a regression. The outcome belongs to the whole system.

A PASS needs an identity

Task T7 ran its test in workspace W2 on revision A.

An edit creates revision B. The earlier receipt still describes A.

Keeping task, environment and revision identities prevents a PASS being assigned to the wrong code.

Stopping does not mean success

Once the contract is verified, the harness can deliver the result.

When the budget runs out, it stops incomplete. These are different outcomes, not stages of success.
