Separate three boundaries

A branch points to commits. A workspace holds working files.

A sandbox restricts effects on files, processes or the network.

A separate copy does not prove confinement. Both boundaries need checking.

A branch does not hold everything

The Git reference points to commit A.

An uncommitted edit changes the file but leaves that reference in place.

Processes and ignored files sit outside this history. A commit does not describe the whole environment.

Two indexes, two copies

Two agents write to separate copies of the same repository.

Each worktree has its own HEAD and index: one edit does not overwrite the other file.

That prevents local file interference. It does not isolate networks or services.

The database is still shared

Worktrees A and B have separate files but share one test database.

A deletes a fixture. B finds zero rows and its test fails.

In a new run, separate service namespaces prevent this specific interference, not every conflict.

A clean merge can still be wrong

One task changes an amount from cents to euros. Another adds a consumer.

They touch different lines, so Git can combine them without a textual conflict.

The consumer expects cents but receives euros. The combined contract still needs a test.

Preserve changes owned by others

The workspace already contained a human edit before the task began.

The agent and another process then add their own changes.

Cleanup must distinguish their owners. Reverting everything would destroy work the agent did not own.
