PRM vs ORM: two ways to reward reasoning

Process Reward Models score intermediate steps. Outcome Reward Models score only the final answer. That difference changes what a system can detect and reinforce.

A PRM can identify the exact step where a plausible-looking solution stopped being valid.

P1Factor the denominator: x² − 4 = (x − 2)(x + 2)+0.95 · correct
P2The roots x=2 and x=−2 are singularities+0.91 · correct
P3Partial fractions with A=1 and B=1+0.31 · error starts here
P4Integrate the two terms and combine logarithms+0.58 · form is plausible
PRM advantageThe evaluator can prune a bad trajectory before the error propagates to the final answer.

An ORM observes only the outcome, so it cannot distinguish all paths that lead to it.

Correct process → correct answerRewarding the final outcome reinforces the right behavior.
Bad shortcut → correct answerThe result is correct by luck, so the shortcut is reinforced anyway.
Correct process → final arithmetic slipThe whole trajectory is penalized even though most reasoning was valid.
ORM limitationA cheap final-answer signal is scalable, but it contains less information about why the result was produced.
PRM · process

Best when the path is verifiable

Formal mathematics, logic, code with partial tests and search procedures where each intermediate state can be scored.

  • Finds incorrect shortcuts
  • Useful for beam/tree search
  • Requires richer supervision
ORM · outcome

Best when the answer is cheap to verify

Tasks with objective final checks where step-level labels would be expensive or unavailable.

  • Simple scalable reward signal
  • Works well with verifiable outcomes
  • Cannot see how the answer was reached
